<h1 align="center">Turbo for Distant Horizons</h1>

<p align="center">
  An addon for <a href="https://www.curseforge.com/minecraft/mc-mods/distant-horizons">Distant Horizons</a> that
  generates distant terrain straight from the world noise, many times faster, with the game's own trees nearby.
</p>

## Features

- **Fast distant terrain.** Replaces the Distant Horizons world generator: level-of-detail terrain is built straight
  from the world's terrain noise, without generating chunks. A far, coarse tile costs about as much as a near one, so
  the horizon fills as fast as the land around you.
- **Many times faster.** In the built-in benchmark against an equivalent of Distant Horizons' rough surface search,
  terrain tiles are 17-19x faster at the same sampling and about 70x faster at full detail. Heights match real
  generation within one block on 90% of columns (the remaining ones are cave openings).
- **Every core at work.** Each terrain tile is split across all worker threads.
- **Real trees nearby.** Close to the player the game's own tree placement is replayed: trees stand where they will
  stand in the real world, with the same species and shapes. Farther away, forests are drawn with approximate trees
  shaped like their species.
- **Surface details.** Snow by temperature and height, ice on frozen water, bare rock on steep slopes, terracotta
  bands in badlands, a biome-specific seabed.
- **No vanishing terrain.** Distant terrain stays on screen while Distant Horizons swaps it for more detailed
  versions, instead of leaving empty squares for a moment when you fly fast.
- **Multiplayer.** Installed on a server, the mod shares the world seed and terrain settings with players who have it,
  and their game generates the distant terrain itself, also on servers without Distant Horizons. The client checks
  that its own terrain data matches the server's and stays out of the way when it does not (terrain mods or data packs
  the player lacks). On a server that runs Distant Horizons, the server generates the distant terrain for everyone,
  and players do not need this mod.

Limitations: the Overworld and the End are generated by this mod; the Nether keeps the Distant Horizons generator
(rough surface only while this mod is enabled).
Villages and other structures appear in the distance only once you have been there. Worlds have to use noise-based
terrain (vanilla and most terrain datapacks do).

## Controls

None. The mod works on its own once installed.

## Crafting

The mod adds no blocks or items.

## Configuration

`config/dhturbo-common.toml`, also editable in game (Mods -> Turbo for Distant Horizons -> Config):

| Option | Default | Meaning |
|---|---|---|
| `enabled` | `true` | Generate distant terrain with this mod instead of the Distant Horizons generator |
| `threads` | `0` | Worker threads, 0 = half of the CPU cores (needs a restart) |
| `full_resolution` | `false` | Compute every terrain column instead of one in four; about 3x slower, sharper distant cliffs |
| `fake_trees` | `true` | Draw trees in distant forests |
| `real_trees` | `true` | Replay the game's tree placement on detailed terrain near the player |
| `share_worldgen` | `true` | Server: send players with this mod the world seed and terrain settings, so they generate distant terrain themselves; turn off if players must not know the seed |

While enabled, the mod switches the Distant Horizons generator plan to "surface only" at runtime, so Distant Horizons
does not spend time regenerating terrain this mod already made. Your Distant Horizons config file is not changed.

## Installation

1. Install [NeoForge](https://neoforged.net) for Minecraft 1.21.1.
2. Install [Distant Horizons](https://www.curseforge.com/minecraft/mc-mods/distant-horizons) 3.3 or newer.
3. Put this mod into the `mods` folder: on the client for singleplayer; on the server and the clients for multiplayer.
   Distant Horizons is needed on the clients; on the server it is optional.

## Building

```sh
./gradlew build
```

The jar is written to `build/libs/`. `./gradlew runGameTestServer` runs the game tests; with the environment variable
`DHTURBO_BENCH=1` it also prints the generator benchmark.
